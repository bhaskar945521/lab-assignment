Question 1:
Using what you observed in Tasks 2 and 3, explain why fs.readFile() does not block the rest of your program, while fs.readFileSync() does.

Answer:
fs.readFile() is an asynchronous method, so Node.js starts the file-reading operation and continues executing the next statements without waiting for the file to finish. This is why the message outside the callback appears before the file content. When the file has been completely read, the callback function runs and displays the content. On the other hand, fs.readFileSync() is synchronous and makes the program wait until the file has been fully read. Therefore, the next statement runs only after the reading operation is completed.


Question 2:
In the Notes App, what could go wrong if two people ran add-note.js at the exact same moment, both appending to the same notes.txt file?

Answer:
If two people run add-note.js at exactly the same time, both programs will try to access and modify the same notes.txt file. Depending on the timing and operating system, the notes may be written in an unexpected order. In some situations, a write operation could also fail or cause unexpected file contents. A database would be more suitable for a large multi-user application because it provides better handling of simultaneous operations. For this small lab, using a text file is sufficient to demonstrate file-system concepts.
